# 性质模式库（prompt 就绪版）与 静态检查/消融 集成方案

> 用途: 直接嵌入 decomposer/critic 的 system prompt；集成方案为设计思路，未改代码。

---

## 第一部分：性质模式库（嵌入 prompt）

你在为 RTL 模块生成形式性质（assume/assert）。**只能从下列模式中选择和实例化,
禁止自由创造时序结构**。模式按一般性排序: 先抽象范式（安全不变量、活性传导、
公平与稳定）, 后具体协议形态（成对窗口、帧形状）。每个模式给出: 形式、语义、
适用场景、失败模式、强化/弱化方向。

记号为【角色通配符】, 实例化时映射到具体信号: {req}=请求线 {grant}=授权/就绪
{fire}=握手完成 {data}=数据拍 {end}=帧末标记 {done}=完成事件原子（布尔组合如
fire&end 实例化时作一个原子, 用 expr 定义） {src}/{dst}=活动指示 {cfg}=配置输入
{Φ}=任意布尔条件原子。

### S1 组合安全不变量（Safety, 含布尔组合）

组合布尔关系式（无时态算子, 或仅 G 包装）:

```
!(vA && vB)              // 互斥: 两请求线不同拍有效
!cfg                     // 配置关闭: 某输入被系统永久禁用 (如 abort)
exprA -> exprB           // 状态译码关系
```
- 语义: 任意可由状态译码/结构直接归纳的布尔性质
- 适用: master 请求互斥、端口方向约束、被禁用配置线
- 特点: 归纳一步可证, 求解代价近似零; **被引用时对应模块必须在案 assert, 禁止只写注释引历史**
- 配置关闭型（`G !cfg`）属**先验/叶子**: 标注 [外部], 与真实系统配置核对后方可使用

### L1 静默传导（Freeze/Quiescence Propagation）

```
(G !srcActive) -> FG (!dstActive)
```
- 语义: 源头活动永久停止后, 下游活动最终永久停止（活性沿依赖链消亡）
- 适用: 流水线/请求链的"关闭"性质的模块级分解; 最一般的目标形式
- 依赖: 通常需要 L3 公平支撑
- 弱化梯度: `FG` → `F`（只需一次静默）

### L2 稳定性（Stability, 请求纪律）

```
valid -> (valid U ready)
```
- 语义: 请求线拉高后保持到握手, 不无端撤回
- 适用: master 的行为义务; 强公平（L3）的配套
- 兑现前提检查: 查 RTL 的 valid 驱动是否含撤销路径（组合取消输入、SRAM 读数据重评估）——若有, 需 S1 的配置关闭型假设（如 `G !abort`）才能成立
- 性质类型: 近安全不变量, 与 L3 的活性互补

### L3 强公平（Strong Fairness）

```
valid -> F ready
```
- 语义: 每次请求最终获得授权（撤回不清账）
- 适用: master↔agent 的授权契约; 蕴含弱形式
- **硬前提**: 必须同时假设 L2, 否则 master 脉冲式"拉高一拍即撤"留下悬空义务（浅反例）
- 经验: 强化到本形式后, 原有参与类假设（L5）可能冗余——须重做消融

### L4 响应到达（Eventual Response）

```
{fire} -> X F {data}
```
- 语义: 请求被接受后响应最终到来（不约束拍位）
- 适用: 及时性契约的基础层

### L5 持续参与（Until 参与式）

```
{fire} -> X ({consume} U {done})
```
- 语义: master 发出请求后保持接收就绪直到完成握手
- 适用: agent 对 master 行为的假设; 弱公平（`F(!v||r)`）时代的配套——**L3+L2 成立时可能冗余, 用前先消融**
- 失败模式: F/X F 形式留出"提前一拍给完就撤"的漏洞——参与类必须用 U
- 弱化梯度: `U` → `X F fire`（仅要求完成, 用于 ready 无法即时的通道）

### W1 成对窗口（##1 窗口化, 固定 2-beat）

```
{fire} -> X F ({mid} ##1 {fin})
```
- 语义: 完成事件是相邻两拍: 非 last 拍的紧邻下一拍是 last 拍
- 适用: 突发长度固定的握手完整性; L5 的弱化替代
- 语法硬约束: 序列必须挂在蕴含右侧 `A -> (!b ##1 (A & b))`; 裸序列及 `&`/`##` 混排（优先级: ## 高于 &）会解析失败

### W2 帧形状（Frame Shape, 拍位承诺）

```
{data} -> (!{end} ##1 {fin})
```
- 语义: 数据拍存在时, 非 last 则下一拍是 last——锚定 last 在帧内的拍位
- 适用: 环境（内存/总线）对数据通道的契约; 是"按突发长度置 last"义务的形式化
- 注意: 只对环境驱动的通道 assume; 对 DUT 自身驱动的通道禁止（自约束）
- 不可省略: W1 断言必须由本先验支撑, 否则 last 拍位漂移产生反例

### T1 端口透传（Contract Transfer）

```
上游端口 assume 模式 Mk  ──[assert 同形 Mk @ 下游端口]──>  下游端口可 assume Mk
```
- 语义: 组合透传模块（arbiter/路由）对契约的搬运
- 硬约束: assert 与上游 assume **逐字符同形**（含 fire/valid 选择、时态前缀）; 信号经网络等价对齐

### T2 无饥饿授权（Starvation-Free Grant）

```
(G (!{otherA} && !{otherB})) -> F {grant}
```
- 语义: 竞争者永久静默时, 本方授权最终出现
- 失败模式: FG 形式在主体自身连续活动时不成立（事务占用使 ready 间歇）——弱化梯度 `FG` → `F`, F 形式配合 L2/L5 即无饥饿

### 先验假设（环境契约, 叶子层）

除 S1 配置关闭型外, 环境契约先验包括:

```
F ready                    // 授权通道最终可用
{fire} -> X F {data}              // 响应到达(L4)
{data} -> ({data} U {done})          // 帧保持(禁 X 前缀)
{fire} -> X F ({rdy} U {fin})        // 数据通路保持
{fire} -> X F ({resp} U {done})      // 响应消费
{data} -> (!{end} ##1 {fin})         // 帧形状(W2)
```
先验必须与权威先验文件（priors.json）逐条对齐; 禁止在先验之外新增环境假设
（若需要, 先走性质模式选择/弱化梯度, 或显式新增 S1 配置叶子并标注 [外部]）。

### 通用弱化梯度表（修改性质时按序尝试, 每轮只改一处）

| 维度 | 强 → 弱 |
|---|---|
| 时态算子 | `U` → `X F` → `F` |
| 永久性 | `FG` → `G` → `F` |
| 终止条件 | fire 形式 → valid/ready 形式 |
| 公平性 | 强公平 `v->F r`（需 L2） |
| 范围 | 全程保持(L5) → 成对窗口(W1) |

### 强化/弱化的对价原则（重要）

每次强化一条性质, 检查是否引入了新的 master 义务假设:
- 强化公平到 L3 ⟹ 需要 L2 稳定性作对价 ⟹ L2 兑现可能需要 S1 配置叶子（`G !abort` 类）
- 弱化不需要对价, 但检查弱化后是否仍支撑下游目标
- 强化后**必须重做消融**: 原有支撑假设可能因此冗余（案例: L3+L2 使 L5 参与假设冗余）

## 第二部分：静态合法性检查的集成思路（不改代码, 仅方案）

### 位置
dispatcher 流水线中, decomposer 产出性质文件之后、`sbt` 编译之前, 插入 **lint pass**。

### 实现形态
新工具 `AGVerify/tools/prop_lint.py`, 输入为生成的 Scala 性质文件, 输出违规清单
（返回给 critic agent 触发一轮自动修复, 修复失败再升级人工）。

### 检查规则（全部可从文本+信号注册表静态判定）

1. **内部信号禁令**: assume 中引用的信号名不在模块端口信号注册表（SignalName 登记的
   io.* 或跨层等价类）中 → 违规（如 read_wrap_out）
2. **自约束禁令**: assume 引用的信号方向为 DUT 输出（从 netlist/RTL 端口方向表获取）→ 违规
   （如对自身 w.last 的帧形状假设）
3. **序列位置**: `##` 出现的位置必须处于 `->` 右侧蕴含式内; `&` 与 `##` 混排必须加括号
4. **X 前缀警示**: `X (A U B)` 形式标记为可疑（过度约束风险, 需 critic 复核一拍帧可能性）
5. **同形检查**: 跨模块对应的 assume/assert 对做模板抽取（算子骨架 + fire/valid 位点）,
   骨架不一致 → 违规（如 TX5 fire vs X5 ready）
6. **悬空检查**: 每条 assume 必须能在其他模块的 assert 集或 priors.json 中找到同形兑现
7. **工程性**: SignalName 已注册、编号不重复、声明先于引用（避免 UninitializedFieldError）

### 与现有工具的衔接
- 端口方向表: 复用 `netlist_graph.py` 的 .sys 数据流图（已有信号等价类, 顺带可判定"同网络"）
- 同形比较: `causal_pairs.py` 的公式解析可扩展为骨架提取
- priors.json: 作为 X1-X6 的权威模板源, lint 的第 6 条以它为锚

## 第三部分：消融验证的集成思路（不改代码, 仅方案）

### 位置
proof 成功（尤其 IC3 证毕）之后、写入 proof_state 的 KB **之前**, 插入 **ablation pass**。

### 流程
```
证毕的性质集 (假设集 A = {a1..an}, 目标集 G)
  for each ai in A:
      A' = A \ {ai}
      以 A' 重跑 BMC(20)         # 只用 BMC, 秒-分钟级; 不重跑 IC3
      通过 → ai 标记冗余
  A_min = A \ 冗余集
  以 A_min 重跑最终引擎(BMC 或 rIC3) 确认
  KB 签名 = (A_min, G)
```

### 必备对照（防空真）
每个模块每轮会话至少一次: 插入矛盾断言 `X F (!v && v)` 确认检查器报告失败;
若矛盾断言通过, 说明当前配置的断言检查无效（如 SERE 丢原子的 BA-is-empty 前兆）, 消融结果全部作废。

### 结果用途
1. KB 条目以最小假设集入库 → 签名更瘦, 跨模块兑现匹配率上升（直接服务 project_path_guidance 的缓存键）
2. 冗余假设的分析结论（为什么冗余）回填 decomposer 的模式选择统计
3. 依赖标注自动化: 消融中"删掉即失败"的假设即该目标的必要依赖, 自动生成依赖表
   （替代本轮手工整理的 P1/P2←A1/A2←PT/MUT 关系）

### 成本控制
- 仅对**收敛后的最终性质集**做消融（迭代中间态不做）
- n 条假设 = n+1 次 BMC + 1 次最终确认; 按本轮实测每次秒-分钟级, 可接受
- 超时预算: 单次 BMC 上限 15 分钟, 超时项标记 unknown 不计入冗余判定

### 与 rIC3 的顺序
消融判定用 BMC; 判定完成后以最小集重跑 rIC3 拿无界结论——避免 n 次 IC3 的开销
（arbiter 每次 rIC3 数分钟, Cache 侧更久）。

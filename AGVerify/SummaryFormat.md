# AGVerify SUMMARY 生成规范（标准模板）

> 每次运行结束后按本规范生成 `results/run_<时间戳>/SUMMARY.md`。
> 数据来源优先级：**outcomes.jsonl 账本（权威）> llm_calls 归档 > 启发式对账（禁用）**。

## 一、必备四要素（最低标准）

| 要素 | 来源（有账本时） | 来源（无账本，如旧运行恢复） |
|---|---|---|
| 每轮的验证目标 | decision 条目的 goal 字段 | llm_calls/*/input.json 的 待验证性质 字段 |
| 生成的性质 | decision 条目的 items[].formula | output.json 的 parsed children/assumes |
| 证明情况 | outcome 条目（phase/verdict）逐阶段 | （旧运行）启发式日志对账 + 注明误差 |
| 性质中的信号 | decision 条目的 items[].signals | output.json 的 signals 完整映射 |

## 二、文档结构（自上而下）

```
1. 运行信息          目标性质/先验/LLM/配置/结局/进度/成果一行
2. 目标演化轨迹      goal 首次出现轮次列表（降层路径一目了然）
3. 每轮摘要表        轮|时间|验证目标|策略|性质数|全局过|IC3★
4. 逐条性质明细表     ★核心表（见下）
5. KB 定理明细       全部证毕定理 + 链段归类
6. 信号定义表        全部信号: 别名/定义(路径或expr)/模块/说明
                     多别名线合并一行, 新入场信号单列
7. 关键行为学发现    writer迁移/技巧落地/复用/命名收敛等
8. 失败与改进        框架bug(已修/遗留)/流程观察
9. 结论
```

## 三、逐条明细表格式（核心规范）

### 3.1 行结构

- **轮 = 每次 agent 调用**（含被拒重问；不做"真实轮/回炉"区分）
- 同一目标第 N 次被分解 → 目标后标 `(×N)`
- goal 变化即降层/换向，goal 不变即回滚重试——由读者据 `(×N)` 自行判断

### 3.2 记录块（每条性质一个块，两行起）

```
行1: 公式（超宽折行）
行2+: 信号（每信号一行，顶格无前缀；超宽续行）
```

公式行与信号行靠内容形态区分（信号行含 `=`）。

### 3.3 列定义与宽度（VSCode 12pt 全屏适配，总宽 ~135 显示列）

| 列 | 宽(显示列) | 内容 |
|---|---|---|
| 轮 | 5 | 调用序号 |
| 验证目标 | 29 | goal（超宽折行，标 ×N） |
| 模 | 3 | 缩写: IC=ICache MA=MemArbiter DP=Datapath DC=DCache T=Tile; 后缀*=assume |
| 性质/信号 | 45 | 公式块+信号块（各自动折行） |
| 结果 | 23 | 三段编码或分类标注 |

### 3.4 结果编码

```
三段式:  G…/M…/I...
  G=全局BMC(Tile) M=模块BMC I=模块IC3
  ✓通过  ✗@N第N拍反例  —未达该阶段  ★完备证毕(IC3)

分类标注(优先于三段式):
  编译✗:枚举未限定   裸 sXxx 枚举成员需模块名前缀(MemArbiterState.sIdle)
  编译✗:占位符泄漏   expr:? 进了生成代码(框架bug)
  编译✗:实例前缀误用 core/arb 等实例名被当路径
  编译✗:未定义信号   信号名在模块中不存在
  编译✗:重复定义     同名 val 声明两次
  截留(未上BMC)      生成后未及全局BMC(队列中/随回滚丢弃)——专用此义
```

### 3.5 分隔符

```
|~~~…|  同轮(调用)内性质之间
|===…|  轮(调用)之间
```

### 3.6 对齐规则

- 全部按**显示宽度**填充（CJK/★/→ 等全角字符按 2 列计，
  `unicodedata.east_asian_width` 判定）
- 分隔行严格按各列宽生成
- 生成后用"管道位置一致性检查"验证（全文所有表）

## 四、每轮摘要表格式

| 列 | 说明 |
|---|---|
| 轮/时间/验证目标(超宽折行,不截断)/策略/性质数/全局过/IC3★ | 每轮一行 |

## 五、目标演化轨迹

```
- 轮 N: `<goal>`        ← goal 首次出现的轮次, 按序排列
```
降层/换向路径由此直接可读。

## 六、结果对账方式（无账本的旧运行恢复专用）

1. 求解器日志解析：每份 AGTileFlatPropSpec_*.log → (模块, 引擎Pono/RIC3, verdict, 信号集)
2. 编译错误分类：AGTileSignal_*.log 的 [error] 行 → 分类规则见 3.4
3. 性质→结果匹配：性质公式中的**信号别名**（≥4字符）∩ 日志信号集
   - 编译错误匹配收紧：**只配该性质自己的信号别名**（防共享别名批量误标）
4. 无命中 → 截留(未上BMC)
5. 必须在表头注明"结果列为启发式对账"

有账本的运行**禁止**使用本节方法——直接读 outcome 条目按 node 关联。

## 七、生成脚本要点（实现 checklist）

```
□ 轮对齐: 逐调用序号(1..N), 不做策略序列匹配
□ 目标提取: input.json 的 待验证性质(当前分解目标, node) 的 formula
   (勿用第一个 "formula" 字段——prompt 其它位置也有公式)
□ 信号呈现: 逐信号一行; port/expr 二选一展示 (port 以 expr: 开头时展示 expr)
□ 折行: wrap(text, cap) 按显示宽, 空格处优先断
□ 全角宽度: dw() 用 east_asian_width
□ 表宽: 明细 ≤135 / 摘要 ≤105 显示列
□ 管道一致性验证: 全文所有表逐行比对管道位置
□ 图例: 表头前的说明块(编码/分类/缩写/分隔符) 与 3.3-3.5 一致
```
